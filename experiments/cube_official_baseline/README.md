# 先对齐官方持续转动任务，再训练定角停稳

## 为什么原课程一直停在5°

`cube_z90` 课程每级都要求“转到目标角度 → 五指同时接触、低速保持1秒 → 连续两次验证≥90%”。5°级的完整姿态容限只有±1°；没有达到门槛就永远不会分配10°等更大目标。旋转超过当前5°目标还会增加误差、扣除进度奖励，所以放大原奖励并不能解除这道门槛。

截至停止时，该课程共182,000个新控制步，仍未通过5°的1秒保持。视频对应73,732步权重的额外20回合检查为：初握20/20、完成转动并重抓0/20，食指有效接触占比约8.94%，回合内平均最长到位稳定时间约0.033秒。这说明“起始能拿住”和“转后能抓稳”是两种能力。

这是课程设计与任务对齐的问题，不能只用“CPU慢”“奖励不够大”解释。7路欠驱动手在转动时通常需要交替松指、重新接触；同时学习转动、定角刹车、五指重抓和精确停稳，显著增加了探索难度。没有完成机械可达性与受控消融，不能据此断言90°在硬件上不可能。

## 仓库官方任务实际做什么

以下依据本仓库固定版本的源码，不把默认配置当成作者权重的完整历史训练日志。

- `sim_rl/mujoco_playground/.../aero_hand/rotate_z.py:32`：控制50ms、仿真10ms、每回合500步（25秒）。
- `rotate_z.py:140`：`motor_target = home_ctrl + action * scale`，是围绕基准的绝对目标，不累积到上一时刻目标。七路scale为`[.02,.02,.02,.02,.7,.003,.012]`。
- `rotate_z.py:169`：物体世界高度低于−0.05 m时终止；没有五指接触、精确角度或停稳门槛。
- `rotate_z.py:248`、`:289`：奖励为`0.05 * (ω_worldZ − Σ(a−a_prev)² − 100*掉落标记)`。linvel/pose/torques/energy的默认权重为0。
- 官方没有直接惩罚横向角速度，也没有固定顶面的约束。`pose`表示手关节姿态代价，且默认权重为0，不代表方块姿态保持。平均Z速度为正允许同时存在翻滚。
- Actor输入14维：6个腱长度、1个拇指外展角、7个历史动作；Critic为81维仿真特权信息。Actor不直接看到魔方朝向或90°目标。
- reset对手关节加噪声，方块位置在`[.1,0,.05]±.01 m`内，朝向随机；官方还提供质量、摩擦、质心、阻尼等域随机化。
- `config/manipulation_params.py:156`：默认3亿控制步、8192环境、Brax PPO、网络512/256/128，gamma0.97。Playground面向MJX/GPU大规模并行。
- 官方模型为50mm、69.2g方块；上一轮自建任务为57mm、约78g魔方，摩擦、初态、安装高度、物理步长和求解设置也不同。

历史动作有一个需要保留的时序细节：官方step先构造下一观测再更新`last_act`，所以在控制时刻t，观测包含a(t−2)。当前78维自建任务使用a(t−1)，其训练/回放内部是一致的；加载官方权重时必须按官方时序适配。

## 当前纠正后的第一步

本目录是**官方任务目标的原生MuJoCo CPU微调基线**。保持官方XML、50mm/69.2g方块、原始约20°掌面倾角、世界Z轴、reset分布、传感器噪声、绝对电机目标、动作历史顺序及奖励。没有先达到5°再晋级的门槛，也没有五指同时接触的旋转门槛。

这一步明确使用官方小方块作受控基线，不声称已经把57mm魔方训练成功。当前57mm场景、准备状态、旧训练检查点和视频均保留。手的原有20°倾角没有补偿。

为利用CPU预算，加载仓库附带的作者actor和critic，而不是重新从零积累数亿步。导出文件包含固定观测归一化统计。64组观测的Brax→PyTorch确定性动作最大差约3.50e−7、价值最大差约5.96e−7。Actor的14维输入与Critic的81维输入分离，额外真值不会泄露给Actor。

CPU微调与官方完整训练的区别也明确记录：

- 原生MuJoCo + PyTorch/SB3，4个CPU环境；不是8192个MJX环境。
- 保留作者网络和冻结观测统计，新建优化器。SB3探索使用以`tanh(作者均值)`为中心的裁剪高斯，未恢复Brax完整的状态相关tanh-normal分布。
- 暂时固定模型参数，先核对基准；未复刻官方整套域随机化。reset位姿分布相同，但NumPy随机流不与JAX逐位一致。
- 微调学习率1e−4、gamma0.97、rollout128×4、batch128、epochs4、entropy0.001；网络仍512/256/128。

微调检查点优先按25秒高度存活率、再按官方回报选模。每131072步评估20个固定初态，每65536步保存。预算沿用原24小时实验的绝对截止时间：**2026-11-13 02:34:14 UTC / 北京时间10:34:14**。该第一阶段不会自动宣称已完成90°停稳。

## 如何判断第一步有进步

分别报告Z角速度、横向角速度、回报、25秒高度存活率、物体距掌心距离和偏离纯Z转动的姿态变化。不能把“没越过高度阈值”当成抓持成功，也不能把世界Z角速度积分当成净偏航角或完整旋转圈数。

实际需要依次完成：

1. 在官方基线中学会持续转动，建立作者权重与CPU适配的性能基准。
2. 加入有效操作区域、侧翻/横向角速度约束，迁移至57mm魔方，验证稳定单轴转动。
3. 再增加目标角度和朝向观测，训练接近90°时减速、重新抓稳、连续保持1秒；保留最终完整姿态和停稳验收。

第二、三阶段必须各自形成新配置和独立评估，不能把本目录的角速度奖励当作最终验收。原作者14维Actor没有直接物体目标朝向输入，后续不能仅改变回放停止时间就声称已经学会“看到90°并停住”。

## 运行

使用已有`aero-rl-reference`环境导出可信的仓库权重：

```bash
JAX_PLATFORMS=cpu /workspace/.venvs/aero-rl-reference/bin/python -m experiments.cube_official_baseline.export_source \
  --weights ros2/src/aero_hand_open_rl/aero_hand_open_rl/ppo_TetheriaCubeRotateZAxisTendon_20250926_152920 \
  --output experiments/cube_official_baseline/artifacts/source/author_actor_critic.npz
```

然后使用现有`aero-cube`环境：

```bash
python -m unittest discover -s experiments/cube_official_baseline/tests -v
python -m experiments.cube_official_baseline.train \
  --source experiments/cube_official_baseline/artifacts/source/author_actor_critic.npz \
  --output experiments/cube_official_baseline/artifacts/official_warmstart_v1 \
  --deadline-at 2026-11-13T02:34:14.079538+00:00 --envs 4
```

恢复时加`--resume <检查点目录>`，保持原截止时间。独立评估：

```bash
python -m experiments.cube_official_baseline.evaluate --checkpoint <检查点目录> \
  --output <报告.json> --episodes 100 --seed-start 50000000
```

`status.json`记录实际进程与最新步数；`author_initialization_evaluation.json`是微调前的20回合基准；`progress.jsonl`保留后续同一任务的验证。导出、加载、推理、物理循环正常执行只是实现验证，任务表现以独立数据为准。

## 2026-11-12微调前基准实测

固定20个NumPy随机重置初态（seed10000–10019）、默认传感器噪声、作者原始确定性Actor，CPU原生MuJoCo：

| 指标 | 微调前结果 |
|---|---:|
| 25秒未触发高度终止 | 14/20（70%） |
| 平均官方回报 | +30.49 |
| 每回合平均Z角速度再求均值 | +2.364 rad/s |
| 每回合平均横向角速度模再求均值 | 5.781 rad/s |
| 每回合最大偏离纯Z姿态的角度均值 | 155.68° |

这组数据来自作者权重的CPU适配检查，不是本轮微调已经学到的成果，也不是作者发表的正式指标。不能将它与上一轮“5°+五指保持1秒”的0/20直接比较为成功率提升。它证明作者策略在正确控制语义下能产生明显转动，同时仍明显翻滚，距离最终稳定90°目标有实质差距。

验证记录：11项环境/策略测试通过；4环境2048步训练检查完成；Actor/Critic跨框架确定性推理差异均小于1e−6；第一次正式20回合基准已保留在`artifacts/official_warmstart_v1/author_initialization_evaluation.json`。

首轮131,072步微调后的同20初态验证：高度存活16/20、平均回报+17.05、平均Z角速度1.124rad/s、平均横向角速度模3.549rad/s、最大姿态偏离角均值158.24°。高度存活提高，但转速与官方回报下降，且明显翻滚仍在，不能描述为稳定90°能力提升。该报告保留在`artifacts/official_warmstart_v1/validation/step_000131072.json`。当前CPU训练观测到约800控制步/秒；与旧任务的物理步长、求解迭代及子步接触监控不同，不能将速度差仅归为网络或硬件性能差异。
