# 主任务：整块魔方 X/Y/Z 各转 +90° 并抓稳

用户目标是为解魔方建立可组合动作：整块 `X90 / Y90 / Z90`，以后再加顶层 `U / U′`。本目录优先训练前三个。此前`cube_official_baseline`只优化持续世界Z角速度，属于过渡基线；已保存并停止，不再占用这轮训练算力。

## 动作集合与模型边界

三个正向整转生成24种整块朝向，能把任意一个面送到指定顶面；反向整转在数学上可由三次正向整转组成。结合顶层正反90°可以组合出各面操作。这说明动作集合足够，不代表单手已经具备机械执行能力。

当前仍使用57mm、77.966253g的locked Rubik刚体模型，只学习整块运动。各层还不能相对转动。后续U/U′必须加入真实可分层模型，并验证固定下两层、只施加顶层扭矩的动作；状态识别和求解器也属于后续接口。

## 这次直接训练90°

- 从第一回合就抽取X/Y/Z之一，目标始终为+90°，三个轴共同训练一套条件策略。
- 30°和60°只有单次进度奖励，不要求在这些角度停住或抓稳，也不会阻止继续训练90°。
- 保留原模型约20°掌面倾角、57mm尺寸、质量、摩擦、重力及执行器范围；没有补偿倾角、增加摩擦或外力帮助。
- 使用官方风格的绝对电机目标：`参考握姿电机目标 + 官方每通道scale × action`，最终按执行器范围限幅，不再累加1%小增量。
- 初始0.25秒保持参考电机目标让初态稳定，物体始终是自由刚体。随后所有转动与重抓由策略控制。

成功必须同时满足：完整目标姿态误差≤5°、有向净转角在+90°±5°内、拇指与至少另外两指各法向力≥0.02N、线速度<0.03m/s、角速度<0.5rad/s，连续保持1秒。转动途中允许手指交替松开；掉落、长时间完全脱离手部、持续穿透、超出80mm操作区或接触安装座/地面会失败。每个目标最多12秒。

这次移除了“五指同时接触才能完成”的门槛。五根手指仍可参与，目标附近每指接触有边际奖励，稳定支撑以拇指加至少两指验收。单层拧动的夹持需求将单独设计。

## 对齐魔方换面坐标

旧任务的固定手轴与准备握姿中的魔方面法线并不重合（初态有明显偏航差），绕手轴90°不一定属于魔方的24种标准换面姿态。

新任务在初握结束时，从魔方三组面法线中选一组最接近手XYZ的右手正交基，再在本回合及后续动作链中固定它。目标为绕这组固定参考轴左乘+90°。这组三轴穿过魔方中心；策略仍需控制物体位置，没有任何仿真铰链辅助旋转。

在基准初姿态，这样的90°端点保留同一立方体碰撞占据空间，而颜色面确实发生置换。单元测试检查全部24种朝向、每轴90°的端点几何一致性，同时用完整四元数防止“形状对称所以原地成功”。

训练重置覆盖24种颜色朝向、小位置/角度扰动；这些朝向的碰撞几何相同。成功的真实终态可进入各训练环境的局部状态库，供后续目标训练使用。没有在回合中把物体瞬移到目标。

## 策略与奖励

从官方任务CPU基线验证较好的不可变检查点`step_001441792_47e53726`提取操控特征。继承512/256/128网络及14维手反馈归一化统计，新增31维物体真值与目标上下文；Actor输入45维，Critic112维。新增目标输入权重初始为零；以57mm参考握姿校准动作偏置，使确定性初始动作在该握姿约为零。新建优化器、探索分布和值输出，不宣称是原官方训练的原样续训。

这份Actor读取仿真魔方位姿/速度/目标，实机需要对应感知或状态估计；不能只连接七路编码器就期望可靠按角度停住。

奖励以完整90°姿态误差下降为主，反向进度扣分；合法手部支撑下首次到30°/60°给小奖励；接近90°后奖励低速与稳定保持。失去保持时撤回保持势函数奖励，不能反复中断0.99秒保持刷分。成功+200、失败−100；保留速度、横向角速度、动作突变及耗时惩罚。奖励归一化不裁平终局奖励（clip_reward=10000）。

保留2ms物理步长和50ms控制周期。每2ms累计有向转角并检查禁止支撑，每10ms检查接触力、姿态与保持时间，减少此前每个物理子步反复完整监测的CPU开销。不能把稀疏的视频帧当作全部物理判据。

## 分轴验收与连续执行

每32768个环境控制步，以固定初态分别验证X/Y/Z各20回合，不用平均值掩盖某个轴失败。分别保存best_x/best_y/best_z和整体best；30°/60°到达率只作为诊断，不计90°成功。

三个轴各连续两次验证≥90%后，使用每轴100个未用于选模的初态独立评估；另外执行20条`X90→Y90→Z90`动作链，动作之间不重置机械手、魔方、控制目标或动作历史。理想端点连续组合，避免把每次实际误差当成新的完美参考而累计漂移。只有独立分轴和连续动作链均达到≥90%，才标记整块动作库达标。

`start_goal()`只更换目标和任务计时器，不改变物理状态。动作链通过并不代表已经能完成U/U′或完整解魔方。
